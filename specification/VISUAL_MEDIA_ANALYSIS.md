# Visual Media Analysis — implemented audio F1–F2

Audio import and analysis summaries use sortable, resizable tables (Files, Records, Properties, Messages, Block details), with clipboard copying including column headers. Programs appear once in Records; failures and cancellation remain visible in Messages. Native timing diagnostics remain available as table fields rather than a monospaced report.

Waveform rendering selects a cached envelope level according to viewport width, merges extrema on both channels, and draws one filled envelope per channel (a polyline at sample-level zoom). The render count follows pixel width rather than capture length. Sample-level zoom still uses detailed PCM. One decoded program name is drawn above the first visible assigned region of each record. Names shorten with an ellipsis according to the next record's position; full names and evidence remain on hover. Unassigned regions have gray bars and no text labels.

The shared histogram shows all four pulse groups as color-coded stacked counts, with independent group visibility. X axes fit all visible measured durations and enabled comparison references with a small margin, without a forced zero origin or discarded outliers. A single duration still has a nonzero axis range. Gray waveform bars outside selected decoded blocks do not imply silence. Channel choices show Mono for mono captures and Left / Right / Overlay L/R for stereo. Table columns can be resized beyond their initial width; selected rows remain blue with white text after focus moves elsewhere.

Implementation scope approved on 2026-10-10: WAV/FLAC graphical signal analysis and pulse timing/quality diagnostics. Later Phase F blocks for DSK, HFE and QuickDisk require separate approval.

## Entry points and navigation

Main window: **Tools → Analyze Audio (WAV / FLAC)**. Audio import summary: **Visual analysis** (single-source summaries preselect their source). The analyzer is read-only and supports progress/cancellation. Opening another source starts another analysis; cancellation keeps a previous completed result available.

Waveform: wheel zoom, drag pan, Shift+drag to select arbitrary audio, Fit, Selected block, Selected record, mono/Left/Right/Overlay. Zoom reads the visible range through the existing PCM reader; fit uses a bounded min/max envelope. Double-click Records to show the complete record, or Regions to show that exact region. Clicking a region bar or clicking the waveform without dragging synchronizes Records and Regions; selection is marked on the waveform. Selecting an issue navigates to its sample range and corresponding statistics. Arbitrary audio selections clear record/region associations. Region and issue tables preserve exact half-open sample bounds. Regions also expose seconds. Header/Payload selection controls all pulse charts; checkboxes filter the four histogram groups independently.

## Sources and diagnostic model

- Existing `WavPcmStreamReader` and `FlacPcmStreamReader` supply actual PCM. No implicit resampling or rewriting is introduced.
- Existing `WavHeuristicAnalyzer` performs decoding and recovery. Diagnostic trace positions are recorded at existing `SharpMzPulseDecoder` state transitions without changing classification or assembly decisions.
- An optional candidate snapshot supports channel/detector comparisons. A second streaming diagnostic pass reuses the same signal preprocessor and pulse detectors, without running a second decoder or retaining every PCM sample/pulse.
- `AudioSignalAnalysis` owns the report model; `AudioSignalChart` draws bounded primitives, without a WPF control per sample. Base waveform ≤65,536 buckets, zoom approximately two buckets per visible pixel, scatter ≤20,000 deterministically thinned pairs. Histograms retain exact sample-duration counts; screen columns aggregate bins when necessary.

## Layers and boundaries

Waveform is **Captured / measured PCM**. Pulse durations are measured after the existing DC/high-pass preprocessor. Encoder, decoder, manual and visual references share the versioned `PulseReferenceCatalog`; `SharpZ80TimingTable` and `AudioPulseReferences` are compatibility projections. The authoritative reference sources are [CMT_TIMING_REFERENCE.md](CMT_TIMING_REFERENCE.md) (§5.4, §6.4–6.5, §9.3) and [CMT_INTERCOPY_TURBOCOPY_TIMING_REFERENCE.md](CMT_INTERCOPY_TURBOCOPY_TIMING_REFERENCE.md) (§24, §27). It preserves ROM context-dependent LOW values, MZ-700 PAL/NTSC distinctions, Intercopy writer timings, TurboCopy nominal timer OUT0 timings, and separately labelled compatibility waveforms. Receiver decision/read windows are not plotted as generated pulse durations; Ultra handshake is not treated as a SHORT/LONG PWM reference. Nominal timer output is not claimed to be an exact cassette WRITE-edge schedule.

Expand **Pulse references / user values (µs)** in Pulse statistics to enable the reference grid, choose a profile, inspect its source/evidence/context, or enter a name and four positive custom durations. By default the reference follows the selected block's decoder timing (closest documented comparison); manually choosing a reference disables following until re-enabled. Comparison references are marked at their actual durations by a four-lane coloured strip along the bottom time axis. Coincident HIGH/LOW references retain both colours; hovering near the strip shows all nearby values, contexts and provenance. These are exact documented points, not invented tolerance bands. User values live in that analysis window and are included with the selected comparison, grid visibility and group visibility in TXT/CSV/JSON exports. Comparison settings do not alter decoding or classification thresholds. Decoded record/profile associations remain logical decoder results; the analyzer does not synthesize a waveform from decoded bytes.

Trace-backed regions distinguish leader, sync, header/payload bytes and checksum. Missing traces, including reconstructed or duplicate-gap candidates, use available decoder anchors and explicitly say `partial trace`; exact missing leader/sync positions are never invented. Recovered regions are marked separately. Quiet gaps are **estimated** from both channels remaining below 0.005 FS peak in 100 ms windows, not proof of tape structure. Unresolved regions come from decoder assembly failures. Unassociated regions have no fabricated record/channel association.

## Statistics and units

- PCM values: full-scale units (FS). Peak, signed positive/negative peaks, RMS, DC and signed peak asymmetry (`positive + negative`) use actual PCM. Clipping counts samples at either representable rail of the original bit depth. L/R difference is `20 log10(RMS L / RMS R)`; unavailable for zero-energy channels.
- Signal RMS uses selected block time spans. Estimated noise uses unassigned audio, which may contain music, speech, duplicate copies or undecodable tape data. Separation `20 log10(signal RMS / estimated noise RMS)` is explicitly **Estimated**, never laboratory SNR. Zero/absent populations produce missing separation values.
- Channel comparison: complete records, checksum-success candidates, timing error and leader variation (stddev/mean), clipping and estimated noise. Preferred-channel ranking uses complete records, candidate checksum success fraction, clipping, timing error, then leader variation; all underlying evidence is reported. With no complete per-channel records, preference is not assessable.
- Four groups per selected block: SHORT High, SHORT Low, LONG High, LONG Low. Durations and reference values are µs; deviation is percent. Mean, population stddev, min/max and linearly interpolated median/P5/P95 use exact weighted counts. High/Low follows selected decoder polarity/reference conventions, not waveform positive/negative sign.
- Selected-block distributions measure standard ZeroCrossing pulses, including leader/sync. The chosen decoding detector and selective recovery are reported separately; statistics do not pretend to reproduce the reduced Schmitt threshold used during recovery.
- SHORT/LONG classification chooses the nearest reference duration scaled by the candidate timing scale. Outliers exceed 35% residual from that scaled reference; black caps mark histogram outliers; scatter outliers remain red. Histogram groups use vivid blue SHORT High, red SHORT Low, green LONG High and orange LONG Low. The Drift chart and exported window data remain available; there is no Drift values table to populate.
- Drift uses 256-pulse windows (final partial window retained). Timing scale is mean measured/reference ratio; global speed offset is `(1/scale − 1) × 100%`. Each window reports SHORT/LONG means, RMS relative error against the selected candidate scale, and local stddev of timing ratios relative to their local mean. Local scatter is separate from changes between windows and global speed offset; no lab wow/flutter certification is claimed.

## Detector agreement

Pulse agreement matches physical level and end position within max(2 samples, 10% of duration), one-to-one with bounded 64-pulse queues: `2 × matches / (zero-cross pulses + Schmitt pulses)`. Classification agreement is matching SHORT/LONG labels divided by matched pulses.

Candidate agreement is the Jaccard intersection/union of checksum-valid `(kind, byte content)` sets per channel/detector. Repeated copies collapse. Complete-record agreement compares assembled serialized-header + payload content sets. Both reuse existing candidates/assembly; candidate snapshots include selective recovery and therefore do not claim a controlled threshold sweep. Empty populations are unavailable rather than 100% agreement.

## Issues and quality

Use existing `DskIssueSeverity`. Audio codes cover clipping, low level, DC offset, pulse outliers, timing drift/discontinuity, channel mismatch, threshold sensitivity, checksum failure and unresolved regions. Candidate checksum failures can coexist with successfully recovered programs and remain warnings, clearly distinguished from final assembly failures.

Thresholds: clipping >0.1%; RMS <0.03 FS; |DC| >0.05 FS; >1% pulses outside ±35% scaled reference; timing-scale range >3%; adjacent timing-window scale change >10%; detector agreement <95%. Poor means an assembly/no-record error or >2% clipping on any channel; other issues mean Marginal; no configured issues means Good. Thresholds and issue reasons are visible in the window and every report. Executability and later tape loads are not tested.

## Selected audio recovery

Choose an existing record/region or Shift+drag over suspected data, then **Analyze selected audio…**. The recovery preview accepts start/end seconds and an optional expected payload length (1–65535 B). Select ZeroCrossing and/or Schmitt, normal/inverted/both polarities, and all channels or one channel. Schmitt scales are editable (default 0.4; 0.65; 1; 1.4). Each test family is independently selectable:

- **Adaptive**: existing decoder rules, enabled by default.
- **Fixed time scale** (manual only): hold the classifier's SHORT duration at a user-entered microsecond value multiplied by each requested time scale. The reference applies to the classifier's physical LOW half, or the opposite half after polarity inversion. LONG uses the normal decoder's decision boundary around twice SHORT; no sample times are rescaled. This can test an externally known timing instead of learning it from the leader.
- **Fuzzy pulse length** (manual only): choose the nearer SHORT or twice-SHORT duration by relative error, reject pulses beyond the user-entered tolerance, and use that tolerance for leader acceptance. SHORT still adapts from the leader. This is a separate family from fixed timing, not an implicit cross-product.

Lists accept semicolons or whitespace and locale/invariant decimal numbers. Thresholds accept 1–8 values in 0.1–4; fixed timing accepts 10–2000 µs and 1–8 scales in 0.25–4; fuzzy tolerance is 5–60%. Reference tests accept 1–64 profiles and 1–60% explicit relative tolerance. At most 600 passes are possible (10 existing test plans, one header-discovery plan and 64 reference plans, each at eight threshold scales). No selected detector, polarity or family, or an unavailable channel, is rejected before scanning. Unselected tests do not run. Settings are disabled during a scan; cancellation remains available. The automatic importer retains its original defaults.

**Reference profile tests** are an explicit additional manual family. Choose **All profiles** or multiple **Selected profiles** with Ctrl/Shift under Reference test settings. All includes the 18 ROM/copier/project references and locally added user profiles from Histogram → Pulse references. Editing the comparison overlay alone does not activate these tests. Each reference pass classifies SHORT/LONG using the documented logical HIGH and LOW durations (connector inversion maps physical LOW to logical HIGH). Context-dependent ROM LOW widths are accepted as alternatives within the entered tolerance; these are documented durations, not asserted receiver decision boundaries. Equal-distance classes are rejected. A separate, labelled adaptive **Reference header discovery** plan retains headers only and supplies checksum-valid header lengths to later reference passes. This permits a ROM-timed header with a fast copier payload without silently including standard-decoder payloads as reference results.

**Test each pulse at ±0.5 sample** is a common manual setting outside the reference panel. It applies to adaptive, fixed-time, fuzzy and reference classification, and to the labelled reference-header discovery plan. Reference rules compare each individual duration `d`, `d−0.5` (if positive) and `d+0.5` against the selected profile's explicit tolerance and choose the nearest unambiguous accepted SHORT/LONG class. Non-reference rules preserve an already accepted class; when `d` is rejected they test `d−0.5` and `d+0.5` against that classifier's existing boundaries. Conflicting accepted classes are rejected. Leader acceptance includes the same half-sample boundary margin, but the measured duration is retained for leader statistics/adaptation. It does not shift any edge, waveform sample, trace position or sample rate, and does not search ±1 sample or enumerate arbitrary bit combinations. Checksums remain required. Pass/candidate tables record correction state for all test families; reference passes also identify profile, source/evidence and tolerance. Repeated matching passes are diagnostics, not independent confirmations.

**Adaptive zero crossing (peak midpoint)** is a separate opt-in detector for manual decoding and histogram measurement. Schmitt gating finds alternating lobes; the crossing threshold is halfway between adjacent negative and positive peaks. The steepest crossing between those peaks is linearly interpolated and quantized to 1/8 sample. An eighth-sample fixed-point decoder preserves these fractional durations until classification; trace bounds remain on the original sample axis. A bounded 4096-sample ring discards unusable long gaps; no closing interval is fabricated without bracketing opposite peaks. This experimental detector does not change automatic import or the raw PCM waveform.

The scan uses the existing preprocessing/scanners over that bounded WAV/FLAC interval. Exact duplicate candidates, including repeated ZeroCrossing results, collapse; pass counts are diagnostics rather than independent confirmations. Existing checksum and reconstruction/assembly rules determine complete programs. Source identity and cancellation are checked; input PCM is never rewritten.

Programs, raw block candidates, per-pass findings and unresolved messages are separate tables. Passes report test family, threshold, fixed duration/time scale, fuzzy tolerance, detector/channel/polarity selections and checksum-valid counts. Candidates and programs retain the settings of every successful matching pass after deduplication. Complete programs can be saved as MZF with sidecar metadata; selected candidates can be saved as raw bytes, with checksum status explicit. A candidate without a header is not promoted to a fabricated MZF; expected length can help detect a standalone payload. Include enough leader, header and payload when searching for a complete program. The preview remains separate from the main analysis, and cancellation retains the previous completed preview. Additional thresholds do not guarantee recovery or prove executability.

## Arbitrary waveform intervals and multiple rows

In the main Visual analysis window, Shift-drag selects any waveform interval, including audio without decoded blocks. Pulse statistics and the histogram are measured asynchronously for that selection using the shared measurement engine. Used for decoding follows the selected candidate detector, original gate and preprocessing start; explicit comparison choices run Zero crossing, Hysteresis or Adaptive peak. Arbitrary ranges remain labelled comparison measurements. Selecting Regions does the same. Records / blocks and Regions allow Ctrl / Shift multiple selection. Their selected intervals are merged before measurement; overlaps count once and gaps are excluded. Statistics combine exact weighted duration bins, not averages of per-block means or synthetic pulses across gaps. The waveform selection outlines the bounding extent; the statistics header states the number of actual intervals. Left / Right measures the displayed channel; Overlay L/R measures actual `(L + R) / 2` PCM and labels it Mix. Comparison guides do not change the measurement. Source identity checks, cancellation and a short debounce prevent stale results from replacing a newer selection. Measurement never changes waveform zoom. Double-click and Selected block / Selected record zoom controls respect multiple selected rows.

## Manual range histogram, alignment and problem markers

Manual recovery has independent checkboxes for Zero crossing, Hysteresis (Schmitt) and Adaptive zero crossing (peak midpoint). Any nonempty combination runs automatically in one Deep analysis with the selected classification tests, gating scales, channels and polarities. There is no separate Auto mode. The default is Zero crossing. Detector selection is separate from the **Adaptive** classification checkbox. Turning Adaptive classification off remains valid with reference profiles, fixed timing or fuzzy tests selected. Automatic import remains unchanged.

The histogram duration axis supports wheel zoom around the cursor, horizontal drag to pan, and **Fit histogram / Zoom + / Zoom −** controls. Histogram zoom is independent of waveform zoom and From/To. Fit includes every measured duration, including long intervals such as 33 ms; zoom hides offscreen bars and guides instead of accumulating them at viewport edges. The header highlights FULL RANGE or ZOOM / PAN, displays the visible duration range and visible/total pulse counts, and points to Fit histogram to restore all durations. Stacked bars aggregate counts into 4-pixel display bins for legibility; navigation never changes the underlying statistical bins. Group/reference edits and measurement refreshes retain the histogram viewport. Histograms and all statistical counts remain unchanged by navigation.

The recovery preview has a **Visual analysis** tab with **Waveform** and **Histogram** pages. The manual histogram is populated **only by completed Deep analysis passes**. Each pass aggregates the very pulse events consumed by its detector while decoding; no independent histogram scan is performed. It remains empty until Deep analysis runs, and can show pulses even when no program decodes. There are no pass or detector selectors beside the histogram and no history of earlier runs. The latest completed Deep analysis automatically supplies one representative consumed stream: highest number of checksum-valid headers plus payloads, scan-order tie break; within that pass, the detector with most unique checksum-valid candidates in the completed result, measurement-order tie break. Channel and polarity select only stored display data. The displayed provenance identifies the selected test, detector and gate. Repeated thresholds, classifiers, detectors and polarities are never summed as extra physical pulses. All selected detectors still run and appear in Scan passes and candidate provenance. Measured durations are retained unchanged, including rejected pulses and fractional adaptive crossings. SHORT/LONG colours compare them with the pass reference (all documented context targets), fixed SHORT/LONG values for fixed timing, or the ROM800 comparison for adaptive/fuzzy classification; colours do not assert acceptance of a decoded bit. Half-sample tolerance changes decoder acceptance, never the measured histogram durations.

The histogram retains group switches, zoom, reference strip and locally editable user references. Editing comparison guides or navigating never remeasures PCM. Changes to scan parameters, source interval, alignment or selected test profiles mark retained measurements **OUTDATED** until another Deep analysis completes. Failed/cancelled scans retain the previous completed measurements. The independent waveform preview streams transformed PCM only, so selection, zoom and WAV export work before decoding. Comparison guide edits alone do not invalidate a pass; edits to profiles selected for decoding do.

**Ignore near zero (±% FS)** is enabled only for Adaptive zero crossing. Values 0–100 specify a fixed minimum symmetric gate around zero after DC filtering; 0 disables this additional gate. The effective transition threshold is the greater of this gate and the existing envelope-derived gating threshold. Small excursions within the gate cannot establish a new alternating lobe. Original samples remain available for interpolation at the midpoint of adjacent opposite peaks: no PCM, peak time or waveform offset is rewritten. Each completed pass and candidate provenance records the deadband used. This opt-in manual setting does not change automatic import.

Stereo alignment uses the original LEFT time axis. With shift Δ in samples, the aligned right signal is `R'(t) = R(t − Δ)`: positive shifts move RIGHT to the right; negative shifts advance it. Enter signed samples or milliseconds, nudge by one sample, or Reset. Milliseconds round to the nearest sample. The limit is ±2 seconds. Invert right polarity is separate from decoder polarity. These controls are disabled for mono audio.

**Mix (L + R) / 2** averages actual aligned, optionally polarity-inverted PCM samples before preprocessing, histogram measurement, waveform extrema collection and manual decoding. It never averages independently calculated envelopes. A bounded delay buffer retains at most `abs(shift) + 1` samples; long captures are streamed. Positive full-scale inversion saturates within the normalized 24-bit PCM range. The usable interval is `[max(from, 0, Δ), min(to, frameCount, frameCount + Δ))`; no zeros or repeated samples are inserted at the edges. Mix is treated as one synthetic channel, labelled Mix in pass diagnostics. Source sample indices remain on the LEFT axis and are never stretched; neither the source recording nor the main analysis is rewritten.

The manual waveform has an additional marker strip: **red** shows measured anomalous pulse intervals (>35% residual), exact full-scale clipping runs, or adjacent 256-pulse timing windows differing by >10%. **Orange** marks a failed-checksum block or unresolved decoder interval. A checksum failure does not identify a damaged byte; orange ranges and descriptions explicitly say that the byte position is unknown. Full-scale detection respects the original PCM bit depth. Findings are clipped to the measured interval and preserve channel/sample bounds. Up to 4096 measured finding spans are retained; the UI states any additional omitted spans while histogram counts still include all measured pulses. Markers aggregate to screen pixels, keeping rendering bounded at overview zoom.

Hover markers for descriptions; click to select the matching Problems row. Tooltip placement follows the cursor with a gap and four fallback positions. Double-click a Problems row to zoom its waveform interval. Double-click a program or candidate to locate its decoded extent. Sample zoom rereads the same transformed PCM, with cancellation and source identity checks. Shift, channel, detector and histogram refreshes or a completed scan preserve zoom and selection, clamped only to the usable interval; Fit explicitly resets the view. Decoded findings remain associated with the matching interval/transform when histogram display filters change, and are excluded from a different transform/interval. No program association is inferred merely from an undecoded histogram.

## Headerless payload recovery and heuristic parity

Manual **Decode scope → Payload only (no header)** decodes framed data without requiring HeaderValid or inferred MZF metadata. Enter a known length, or opt into **Unknown length / framing boundaries**. Known-length decoding consumes N payload bytes plus two Sharp checksum bytes through the shared decoder. Unknown-size streaming checks bounded framing/reset/selected-end candidates, preserving uncertain length even on a matching popcount checksum; matching separate framed copies can provide corroboration. Partial byte prefixes are retained with checksum unknown. Candidate statuses explicitly distinguish Verified checksum, Checksum match / unverified length, Checksum mismatch and Partial / checksum unknown.

Raw BIN export preserves decoded bytes. A separate **Create MZF with supplied metadata** dialog requires explicit Sharp name/type/LOAD/EXEC and synthetic-header acknowledgement. It never invents original metadata. **Candidates / Recovery** exposes bounded stage/reason/sample/time diagnostics and navigates the waveform; Problems also includes actual decoder reset spans. Logging can be disabled. Candidate data across manual passes is limited to 64 MiB; narrow the interval/tests if reached.

Automatic heuristic recovery also sweeps Schmitt 0.4 / 0.65 / 1.4 through unresolved gaps, including intervals without detected headers. Shared preprocessing/scanners/checksum/assembly remain common with manual recovery. Standard import remains separately selected. The original 710.59-second capture yields the same three programs through Heuristic and Manual Auto; the real 274.30-second headerless stereo capture yields Exploding Fist's 37744-byte payload, checksum 19836, matching the original capture byte-for-byte. ## P0/P1 shared references and pass comparison

Standard WAV/FLAC and heuristic import share native MZ700/MZ800 1:1 classification using checksum-valid header and payload timing. MZ700 comparisons include service nominal and exact PAL/NTSC ROM references from the shared catalog. Both blocks must support the same MZ700 reference and pass the ratio/fit margins; incomplete or conflicting evidence stays NORMAL. Standard byte decoding and checksum handling are unchanged. The resulting MZ700 1:1 profile does not certify the machine's region.

Standard tape import also searches for a fresh framed header after a checksum-invalid header, while retaining conventional duplicate-copy recovery. Either route must produce a checksum-valid header before payload decoding starts. This prevents a false header from hiding later programs at a different speed, including NORMAL 1:4; thresholds and PCM preprocessing remain unchanged.

Manual reference settings remain selectable while reference tests are off. Selecting a reference enables testing and switches to Selected profiles; Ctrl/Shift selects several references. The checkbox is in the same settings section. Reference selection controls pulse comparisons, not an imposed loader identity. Explicit MZ-700 PAL/NTSC export timing applies to imported NORMAL 1:1 and MZ700 1:1 records as well as newly created records; other loader/speed profiles are preserved.

Visual block metrics default to the actual decoding detector. Selective passes replay their original preprocessing interval and gate; reconstructed candidates without a unique origin are labelled Mixed / unknown. Manual histograms still use the latest completed Deep analysis only. A separate Pass comparison tab aligns retained decoder observations and reports First observed mismatch or Unable to align; missing events are not evidence of success. Catalog details include timing kind, machine, stage, evidence, context and source. Full migration, regression evidence and limits: [P0/P1 audit](../docs/AUDIO_P0_P1_REFERENCE_UNIFICATION.md).
