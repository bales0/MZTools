## Implemented

DSK a HFE jsou skutečné dokumenty ve stejném Avalonia shellu jako Tape/QuickDisk.
Disk má vlastní cestu, container variantu, modified/read-only stav, výběr souborů
a sektorů, filtr, obsahovou záložku, viewport mapy i fyzické stopy a rozepsané
properties/hex. Přepnutí karty je zachová. Save a Save As navazují dokument na
ověřený výstup; Export/Convert zachovávají původní binding.

| Oblast | Skutečně připojené chování |
| --- | --- |
| New/Open | Extended CPC DSK a podporované HFE v1/v2/v3; FSMZ/MZ-BASIC/IPLDISK, P-CP/M80, SDS400, LEC DD/HD, MRS, Lemmings, custom raw/interleave a single/multi IPL přes původní Core |
| Soubory | Společná tabulka, filtr, výběr, import MZF/binary, potvrzené delete a export, rename a podporované user/attribute/type/load/execute/lock vlastnosti; neexistující metadata jsou disabled |
| Přenos | Typed clipboard a routovaný drag/drop; cross-disk preview, explicitní cílová jména, kolizní politika, Core kontrola kapacity a metadat; nativní diskové záznamy lze přenést do Tape/QD; CP/M/raw se nevydávají za záznam s původním MZF headerem |
| Mapa | Track a schematický surface pohled pro obě strany; descriptor nebo sector-ID pořadí; Ctrl/Command/Shift, klávesnice, zoom/pan/fit/fit selection, společný výběr soubor–sektor–hex–inspector |
| Analýza a struktura | Core findings, filtr závažnosti, detail s CHRN/ST1/ST2 a přesnými jednotkami/offsety, navigace na sektor, filesystem struktura a textový report |
| Hex/raw/patch | Skutečný sektorový a CP/M block draft, Apply preview/Cancel, raw range import/export s přesným pořadím a délkou, export/apply zdrojovým hashem vázaného patche; raw sektorový import používá stejný Core replacement jako WPF |
| Fyzický detail | Uložené HFE cells/index/weak mask/declared timing versus generované DSK MFM; CRC evidence z Core, omezená on-demand cache; vložený i samostatný pohled sdílejí komponentu a viewport |
| Opravy | Původní bezpečný Open repair, ruční container repair a samostatné potvrzení truncate; nezávislý filesystem repair, defragmentace a explicitní normalizace creator padding |
| Format/compare/convert | Preview nahrazení celého média, logický a fyzický compare report, diff navigace, konverze filesystemů a explicitní export DSK/HFE variant přes Core |
| Boot/CP/M | Bootstrap track/header import/export, metadata i potvrzené clear, instalace kompatibilního boot/system zdroje, původní hashované bundled systémy, custom DPB/maps a uživatelské layout/boot profily |
| IPL a COM | Single/multi program build, přidání, odstranění, rename, komprese, tlačítkové pořadí i lokální drop reorder, capacity/memory validace a Native COM import přes původní Core |

New single/multi IPL po volbě profilu vyžaduje programy; bez alespoň jednoho
platného programu nevzniká uložitelný obraz. Odstranění posledního programu se
odmítne bez ztráty dosavadního dokumentu. Jde o konsolidovaný tok kolem stávajícího
writeru, který vyžaduje neprázdný programový seznam. Nepřibyl nový undo engine.

U HFE bez bezpečné filesystem projekce zůstává dostupná fyzická inspekce a přesná
Save As kopie původní varianty. Neznámá encoding nebo timing/weak/index vlastnosti
se nezploští jen kvůli aktivaci editoru. HFE-to-HFE export serializuje a ověřuje
původní fyzický model; nepoužívá ztrátovou DSK projekci jako mezikrok. HFE-to-DSK
a DSK-to-HFE mají konkrétní Core loss report před potvrzením.

Výběr mapy nevyvolává nevyžádaný scroll celé obrazovky. Malý viewport používá
posun obsahu, zalomené záložky a společný detailový inspector. Tabulky mají
omezený viewport, fyzické stopy používají existující cache maximálně osmi stop.
Kreslení nečte soubory ani neprovádí decoding/filesystem analýzu.

## Ochrana dokumentu a originálu

Oprava při Open používá `DskOpenCoordinator` a původní deterministické plány.
Zdravý disk neotevírá opravný dialog. Cancel zachová dosavadní karty a zdrojové
bajty; Apply vytvoří paměťovou kopii s `RequiresRepairSaveAs`. Nejednoznačné CHRN,
chybějící stopy nebo FDC stav nejsou důvodem k vymyšlení chybějícího obsahu.
Container repair a filesystem repair jsou různé příkazy a různé preview.

Opravená kopie se v Avalonia uloží **pouze do nového, neexistujícího cíle**.
Existující soubor, originál, hardlink i symlink/alias cíle se nepřepíše po obecném
overwrite potvrzení. Atomic transaction používá no-replace commit; soubor vzniklý
mezi preview a commitem způsobí odmítnutí. Běžný Save As zdravého média stále
umožňuje potvrzenou kolizi. To odpovídá výslovně schválenému zpřísnění F5.

Nový hostový adaptér zachytí identity a SHA-256 originálů, ověří je při získání
read leases a znovu před commitem. Linux používá systémový
[statx nad otevřeným deskriptorem](https://man7.org/linux/man-pages/man2/statx.2.html),
Windows existující systémové file identity API. Linux file-share flag není
vydáván za zákaz zápisu jiným procesem. Neověřitelná identita zápis blokuje.
Nové knihovny se neinstalují ani nedistribuují.

U běžného diskového Save se kontroluje také hash zdroje a kolize ostatních
otevřených dokumentů. Výstup se připraví/parsuje/ověří před commitem; cesta,
Core binding a clean stav se změní až po úspěchu. Save As z read-only zdroje
obnoví i skutečné UI capabilities kopie. Save on close u validního draftu nejprve
nabídne konkrétní Apply preview; Cancel/chyba ponechá dokument i buffer.
Zápis není vydáván za univerzální ochranu proti výpadku napájení nebo libovolným
souběžným zásahům do celého filesystem namespace.

## Změněné oblasti a zachované algoritmy

- `Documents/DiskSession`, `DiskLoader`, `DiskOperations`, `DiskDialogs`:
  skutečný doménový adaptér, snapshoty, drafty, file-set save a předcommitová kontrola.
- `Views/DiskWorkspace`, `Controls/DiskMap`, `DiskTrackView`, `DiskInspector`,
  `DiskPhysicalPanel`: společné komponenty a interakce; samostatný fyzický detail
  používá tutéž komponentu jako vložený panel.
- `ViewModels/ShellDiskCommands`, `ShellDiskDetails`, `Platform/DesktopDiskDialogs`,
  `RepairSourceProtection`: command/dialog/platform hranice. Shell, media loader,
  coordinator a lifecycle byly cíleně doplněny o diskový dokument.
- Core: `DskDocument.Save` sdílí dokončení bindingu přes úzký `CommitSaved`,
  `AtomicFileTransaction` má volitelnou předcommitovou kontrolu a
  `CorePlatformServices` lze nakonfigurovat pouze pro repair bez FLAC backendu.
- `DskImportPolicy` je přesně vyčleněná původní čistá metoda z WPF editoru.
  `DskEditorWindow.xaml.cs` ji deleguje. Rekonstrukce původního těla vrací přesný
  hash F2 inventory; nezměnil se význam názvů importu.
- Přibyly diskové integrační/headless testy, `DiskScenario` v nativním smoke,
  souhrn/validátor F5, dokumentace, gallery a záznamy schválení.

DSK/HFE kodeky, CP/M/FSMZ/MRS a IPL filesystemy, IPL readery/writery i diskové
factory algoritmy jsou přímo porovnané s HEAD a nezměněné. Golden soubory,
boot obrazy, oba produkční Capture projekty a referenční pulse katalog nejsou
přepsány. WPF zůstává referenční aplikací. Žádný nový NuGet balíček, font,
nativní runtime distribuce, CI/release ani odstranění WPF.

- macOS, ARM64 a všechny kombinace skutečného monitorového DPI. Render 125/150/200 %

  raw pointer mapy, clipboard codec a klávesnice mají testy; to nenahrazuje OLE/DnD

  spuštění audio capture. Windows/Linux repair identity je ověřena na dostupných
  filesystémech; neověřitelná platforma zůstává fail-closed.
- Pokročilé dosud neportované QuickDisk surface/cell/floating forenzní funkce
  zůstávají evidencí F4. Diskový surface nepředstírá jejich dokončení.
- F6 plný offline Audio Analyzer, F7 recorder UI, F8 OS audio backendy/FLAC a F9
  zbývající batch UI, CI/distribuce a odstranění WPF jsou nadále mimo tuto etapu.

## Použití a reprodukce

Spuštění: `dotnet run --project src/MZTools.Desktop/MZTools.Desktop.csproj`.
New disk nabídne profil a container; geometrie a raw pořadí se validují v Core.
U existujícího Format zůstává container stávajícího dokumentu; změna containeru
patří do Export converted container. U IPL se vyberou programy před vytvořením.

Open zdravého DSK/HFE otevře kartu. Files a inspector sdílejí výběr s Map a Hex.
Změna názvu/vlastností je draft: Apply properties ukáže preview, Cancel edits jej
vrátí. Hex používá původní počet bajtů a samostatný Apply preview. Nástroje jsou
v rozbalovacím Disk tool + Run tool; nepodporovaná operace oznámí konkrétní Core
důvod. Cross-disk paste nejprve nabídne cílová jména a politiku kolizí. Save As
opraveného obrazu vyžaduje nový soubor, nikoliv existující kopii s potvrzením.
